# SHA-524 — spec

Task (Linear SHA-524): extend the side-effect gate of code-runner.
1. `allow_side_effects` accepts a new entry form `"srv.tool:N"` (N positive int): at most N calls of that tool within ONE `execute_code` run; the (N+1)-th raises `PermissionError` that says the budget N is exhausted. Without `:N` behavior is unchanged. `"srv.*:N"` — decide whether it makes sense (budget shared across the server's tools) and implement it consistently or reject it with a clear error; state your choice in the report.
2. Fingerprint of a gate-refused call = server.tool + stable hash of its arguments (canonical JSON, sorted keys). When `session_id` is set, store refused fingerprints in the session; a repeat of the same fingerprint with UNCHANGED permissions (same allow_side_effects/allow_tainted for that tool) gets the same refusal immediately, with a marker «повтор» (e.g. prefix `повтор отказа:`). If permissions changed, evaluate normally. Without session_id — nothing persists (refusal is just the normal one).
3. Both paths must work under subprocess isolation (default) and `CODE_RUNNER_ISOLATION=inprocess`. Calls are proxied from the child to the parent — find where the gate lives (start with `codegraph query allow_side_effects` / `codegraph callers` in the repo root; `.codegraph/` exists) and put the budget counter where the run-level state already lives (taint state is run-level too — SHA-481, follow that pattern; skill-side proxies SHA-502 and the secret gate SHA-503 must keep working).
4. Update the `execute_code` docstring in server.py (allow_side_effects section) and one line in CLAUDE.md § Security next to the existing gate bullets. Match surrounding style.
